# Daily Plan

Most people start the day by reacting: inbox first, then whatever is loudest. By noon the important work has not been touched. This skill builds a 10-minute morning routine with your agent that flips that order. Plan first, react second.

This is the free sample of the pack. If it earns its keep, the other five skills are waiting.

## The core idea: top three

Ask the user: "If today could only produce three results, what would they be?" Not ten. Three. Everything else is bonus.

Three forces a real choice. Ten is a wish list. The agent's job is to hold the user to three and push everything else to a "later" list that still gets captured, just not today.

## The 10-minute routine

Walk the user through this every morning, in this order. Do not skip steps; each one feeds the next.

**1. Yesterday's leftovers (2 minutes).** Ask: "What did not get done yesterday?" Anything unfinished goes on today's candidate list or gets an explicit new date. Nothing is allowed to silently evaporate. Silent evaporation is how tasks die.

**2. Today's inputs (2 minutes).** Ask: "What is already on your calendar, and what came in overnight?" Meetings, deadlines, anything with a fixed time. These are the immovable blocks. The plan gets built around them, not through them.

**3. Pick the top three (3 minutes).** From leftovers plus new inputs, pick three priorities. For each one, ask the user to state it as an outcome, not an activity.

Bad: "Work on the report."
Good: "Finish the draft of the Q3 report and send it to Priya."

If the user names more than three, that is fine. Write the extras down under "later this week" so they feel captured, then return to the three.

**4. Time-block the big one (2 minutes).** Take priority number one and put it on the calendar first, in the user's best working hours. Morning for most people. The agent should ask: "When is your sharpest hour?" and block it. Everything else flexes around this block.

**5. The shutdown line (1 minute).** End with: "At the end of today, tell me what got done and what did not." This sets up tomorrow's step 1 and closes the loop. A plan with no review is a wish.

## The example

Show the user what a finished plan looks like. Concrete beats abstract.

> TOP THREE
> 1. Finish Q3 report draft, send to Priya (9:00-11:00, deep work block)
> 2. Call the dentist to reschedule (15 minutes, between meetings)
> 3. Review and approve the invoice from Marco (before 5pm deadline)
>
> LATER THIS WEEK
> - Start the holiday travel research
> - Clean out the downloads folder
>
> FIXED TODAY
> - 11:30 team standup (30 min)
> - 2:00 dentist is CANCELLED, needs rescheduling (see #2)

Point out: the day has three outcomes, one protected work block, and nothing important is floating.

## Rules the agent enforces

Teach the agent these guardrails so the routine stays useful:

- **One big rock.** Priority one must be the hardest, most important thing, not the easiest. If the user's top three are all easy wins, ask: "What are you avoiding?"
- **No phantom time.** If the calendar shows six hours of meetings, say so: "You have about two usable hours today. Pick one priority, not three." Honesty beats optimism.
- **Capture, don't cram.** When new tasks come up mid-routine, write them under "later this week." The plan is allowed to have a parking lot. It is not allowed to have eleven top priorities.
- **Outcomes, not activities.** Every priority must be checkable at the end of the day. "Work on X" is not checkable. "Finish X and send it to Y" is.

## The practice exercise

Do the routine with the user right now, on today, for real. Do not use a hypothetical day. Walk the five steps, write the plan down in a file or note the user keeps, and set the expectation: "Tell me tonight what got done."

Tomorrow morning, open with step 1 using last night's report. After three days the user will feel the difference, which is the whole point of this skill being the free sample.

## When this skill is done

The user runs the 10-minute routine on their own each morning and can explain why three priorities beat ten. Point them at `weekly-review` next: the daily plan handles today, the weekly review makes sure the days add up to something.
